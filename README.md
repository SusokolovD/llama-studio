# Llama Studio

Нативный менеджер llama.cpp на C++17 и Qt Widgets (Qt 5.14+ / Qt 6). Русский интерфейс, тёмная тема, каталог аргументов из JSON, отдельная вкладка процесса и журнала.

## Запуск

Опубликованные сборки: [GitHub Releases](https://github.com/SusokolovD/llama-studio/releases). Распакуйте Windows x86 static ZIP и запустите LlamaStudio.exe. Приложение может управлять внешними 64-битными бинарными файлами llama.cpp.

Статическая сборка без Qt/OpenSSL DLL: `dist/LlamaStudio-static/LlamaStudio.exe`. Инструкция по повторной сборке: [STATIC-BUILD.md](STATIC-BUILD.md).

Динамическая сборка: `dist/LlamaStudio/LlamaStudio.exe`.

1. Укажите папку с готовыми бинарными файлами llama.cpp. Приложение ищет `llama-server` и `llama-fit-params` в выбранной папке, `bin`, `build/bin`, `build/bin/Release`, `build/Release`, `Release`. Поддерживается также объединённый исполняемый файл `llama` с командами `server` и `fit-params`.
2. В разделе «Модели и адаптеры» отметьте `--model` и выберите GGUF. Здесь же находятся multimodal projector, draft-модель, LoRA, control vectors и каталог моделей router. Для LoRA/control vectors можно выбрать несколько файлов. Поля scaled используют формат llama.cpp `FNAME:SCALE,...`.
3. Введите размер контекста внизу и нажмите «Подобрать параметры». Значение `0` передаёт `--ctx-size 0`: автоподбор до максимального контекста модели с учётом доступной памяти. Результат fit заменяет контекст, GPU layers, tensor split и tensor overrides в текущем конфиге.
4. Нажмите «Запустить сервер». На вкладке журнала отображаются фактическая команда процесса, stdout/stderr и его состояние. Готовность проверяется через `/health`; Web UI открывается в браузере. Кнопка остановки сначала запрашивает завершение, затем через 5 секунд принудительно завершает процесс.
5. «Сохранить как…» записывает полный JSON с каталогом, значениями, включёнными параметрами, путём к llama.cpp и контекстом fit. «Открыть конфиг» восстанавливает его. Автосохранение не включено: перед закрытием сохраняйте изменения вручную.

Предпросмотр показывает следующую команду, журнал — команду текущего/последнего процесса. Изменение настроек во время работы не перезапускает сервер. Ключи в предпросмотре скрыты; «Копировать команду» копирует рабочую команду с ключами. Сохраняемые конфиги содержат введённые ключи открытым текстом.

При запуске приложение автоматически проверяет [релизы llama.cpp](https://github.com/ggml-org/llama.cpp/releases). Кнопка «Проверить обновления» повторяет проверку по запросу. Проверка идёт в фоне через публичный GitHub API, включая pre-release builds. Установленная версия определяется командой `llama-server --version` из выбранной папки; если бинарный файл не найден, показывается последний релиз без сравнения. «Открыть релиз» открывает страницу скачивания в браузере. Сбой сети или лимит API отображается в строке проверки и не мешает запуску сервера.

## Обновление и сборка llama.cpp из исходников

Откройте вкладку «Сборка llama.cpp» и задайте:

- Корень Git-репозитория исходников с `.git` и `CMakeLists.txt`.
- Папку готовых бинарников: абсолютный путь или путь относительно исходников. Для Visual Studio обычно `build/bin/Release`, для Ninja — `build/bin`. В этой папке должен непосредственно лежать llama-server.exe или объединённый llama.exe.
- Отдельную папку назначения. По умолчанию это `llama-build` рядом с программой; путь можно изменить.
- JSON команд сборки: `program` и массив строк `arguments`. Выполнение идёт в папке исходников. Редактор проверяет JSON до запуска Git и сборки.

Пример:

```json
{
  "schemaVersion": 1,
  "name": "CMake Release",
  "commands": [
    {"program": "cmake", "arguments": ["-S", ".", "-B", "build", "-DCMAKE_BUILD_TYPE=Release"]},
    {"program": "cmake", "arguments": ["--build", "build", "--config", "Release", "--parallel", "4"]}
  ]
}
```

Файл `build-commands.json` рядом с exe задаёт исходные команды; при его отсутствии используется встроенная копия из `resources/build-commands.json`. Кнопки «Загрузить JSON команд» / «Сохранить JSON команд» позволяют хранить отдельные рецепты для CPU, CUDA, Vulkan и разных генераторов. Импорт рецепта не меняет пути исходников и назначения. Прежние строковые команды JSON-профилей мигрируют в массив объектов. Незавершённый JSON в редакторе можно сохранить вместе с полным профилем для продолжения редактирования, но запуск и экспорт отдельного рецепта требуют корректного JSON.

Отредактируйте генератор, архитектуру и флаги backend под свой установленный компилятор и GPU. Запускаемые программы должны быть доступны в PATH либо задаваться полным путём. Путь с пробелами передаётся одной строкой массива, без дополнительных кавычек; обратные слеши в JSON экранируются, либо используйте `/`. Для скрипта задайте `program: "powershell.exe"`, `arguments: ["-File", "build.ps1"]`. Оболочка автоматически не добавляется.

Кнопка «Git pull → собрать → скопировать» сначала выполняет `git pull --ff-only`. Программа не сбрасывает изменения, не делает stash и не разрешает конфликты за пользователя. Ошибка pull или любой команды прекращает цепочку. Журнал показывает текущую команду и вывод процессов, отмена доступна во время работы.

После успешной сборки все обычные файлы папки бинарников, включая DLL и вложенные ресурсы, копируются в назначение с заменой совпадающих файлов. Прочие файлы назначения сохраняются. Новые файлы сначала подготавливаются отдельно; при ошибке установки выполняется откат замен. Если восстановление невозможно из-за внешней блокировки файлов, журнал указывает папку резервных копий. Символические ссылки и пересекающиеся пути не принимаются.

Сервер и fit должны быть остановлены. После успешного копирования программа автоматически выбирает папку назначения для запуска llama.cpp. Пути и команды сохраняются в секции `build` JSON-конфига. При закрытии приложения активная сборка отменяется; обычная отмена на Windows завершает дерево процесса команды.

Версия приложения видна в шапке, заголовке окна и свойствах exe. Иконка llama/терминала встроена в exe и отображается в окне и панели задач. Исходный рисунок: `resources/app-icon.svg`; PNG/ICO можно перегенерировать командой `python tools/generate_icon.py` (нужен Pillow).

## Каталог JSON

Названия, пояснения и подсказки встроенного каталога переведены на русский. CLI-флаги и значения для llama.cpp сохраняются без перевода. Исходное описание хранится в `originalDescription`; тексты перевода — в `resources/parameters.ru.tsv`. Английские описания старых конфигов обновляются при загрузке из встроенного каталога, значения параметров сохраняются.

`resources/parameters.json` содержит 261 запись из [server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). Снимок исходного README хранится рядом. Копия `parameters.json` рядом с exe читается при запуске; если её нет, используется встроенная. Другой каталог можно открыть кнопкой «Загрузить каталог JSON».

```json
{
  "schemaVersion": 1,
  "groups": ["Common params", "Sampling params", "Server-specific params"],
  "parameters": [
    {
      "name": "--ctx-size",
      "label": "Размер контекста",
      "type": 1,
      "default": 0,
      "priority": 2,
      "group": "Common params",
      "enabled": true,
      "value": 8192
    }
  ]
}
```

Типы: `0` строка, `1` целое, `2` вещественное, `3` bool, `4` путь, `5` выбор (`choices` — массив строк), `6` два отдельных аргумента (`START END`). `default: null` означает наследование из llama.cpp/модели либо отсутствие фиксированного значения. В `type` хранится числовой enum; значения `choices` передаются в CLI как строки.

Меньший `priority` означает более высокую позицию. «Частые параметры» показывает записи с приоритетом меньше 100. Это начальная экспертная сортировка, без сбора статистики; порядок можно менять в JSON. В каждой группе сохраняется сортировка по приоритету. Поиск выполняется по всему каталогу. `enabled` определяет, передаётся ли параметр в процесс. Отключённые параметры остаются на усмотрение llama.cpp. Служебные команды и удалённые опции доступны для чтения, но заблокированы для запуска сервера.

`negative` задаёт парный флаг для bool=false, например `--no-warmup`. `aliases` позволяет распознавать короткие аргументы результата fit. Перегенерация каталога из снимка: `python tools/generate_catalog.py`. Сложные новые параметры upstream следует проверять после генерации.

## Помощник настройки: чат, агентский код и несколько GPU

Нажмите «Помощник настройки» при остановленном сервере. Выберите GGUF и прочитайте метаданные: название, архитектуру, обучающий контекст, наличие шаблона чата и количество частей. Читается заголовок и метаданные GGUF v2/v3 little-endian; тензоры модели не загружаются в память. Неподдерживаемые или повреждённые метаданные не интерпретируются как корректные.

Укажите задачу, контекст одного диалога и число одновременных диалогов. Для чата начальный ориентир — 8192 токена, для агентского программирования — 32768, если модель поддерживает такой контекст. Общий `--ctx-size` равен произведению контекста диалога и количества слотов. Помощник не применяет RoPE-масштабирование для обхода обучающего лимита.

«Найти GPU через llama.cpp» запускает `--list-devices`. Отметьте нужные устройства одного backend, проверьте их свободную память и резерв на каждую карту. Доступен ручной ввод и режим CPU. Для нескольких GPU предлагается `layer`; пропорции по свободной памяти показываются как ориентир, а `tensor-split` остаётся незаданным для точного подбора утилитой fit. CUDA и Vulkan могут представлять одну физическую карту дважды — выбирайте один backend. Несколько GPU не гарантируют ускорения: важны соединение между картами и скорость каждой из них.

По умолчанию помощник сохраняет текущие настройки сэмплирования: температура зависит от модели, а не только от задачи. Можно явно выбрать пример для чата или кода и проверить его по карточке модели. Родной шаблон, reasoning-параметры, модель и адаптеры не заменяются общим пресетом. Для агентской IDE нужны обученные вызовы инструментов и совместимый Jinja-шаблон; серверные `--agent`/`--tools` не включаются автоматически. Подсказки по режимам также доступны в карточках ключевых параметров при наведении мыши.

Перед применением показаны все изменения и предупреждения. «Применить в конфиг» обновляет настройки, «Применить и запустить fit» сразу запускает подбор размещения. Выбор режима помощника сохраняется вместе с конфигом. Запас под проектор, LoRA, draft-модель и другие GPU-приложения задавайте отдельно; утилита fit оценивает основную модель.

Оценка KV-памяти доступна только для ряда стандартных attention-архитектур с известными размерами. Она не включает вычислительные буферы, особенности реализации, выравнивание и дополнительные модели. Для MLA, гибридных и прочих архитектур численная оценка не выдаётся. Окончательные параметры проверяйте через fit, журнал памяти, скорость и качество на своей задаче.

## Подробные пояснения и расчёт контекста

В помощнике три вкладки: «Рекомендации», «Память» и «Справочник». Справочник объясняет температуру, top-k/top-p/min-p на численных примерах, штрафы повторов, seed, контекст и слоты, резерв VRAM, различия весов/KV/вычислительных буферов и порядок настройки для чата и агентского кода. Раздел «Промпты для кодинга» содержит структуру запроса, полезные формулировки, передачу кода и логов, готовые шаблоны реализации, отладки, ревью и IDE-агента, особенности разных моделей и разбор неудачных ответов. Справочник доступен даже до выбора модели или GPU; шаблоны можно выделять и копировать.

Во вкладке «Память» расчёт меняется вместе с контекстом, числом диалогов и форматом кэша. Показаны текущая оценка, стоимость токена KV, таблица окон 4K–64K плюс выбранное окно, сравнение f16/q8_0/q4_0 и бюджет каждой GPU после резерва. Размеры K/V берутся из GGUF, если указаны отдельно. Расчёт консервативно ограничен известными стандартными attention-архитектурами без SWA; для неподдерживаемых схем показано объяснение и явно обозначенный учебный пример вместо прогноза для модели. Размер файла GGUF и оценка KV не подменяют измерение всей VRAM: остаются рабочие буферы и особенности размещения.

## Сборка и проверки

Для проверенного на этом компьютере Qt 5.14.2 / MinGW 7.3 (x86):

```powershell
$env:PATH = 'E:\Qt\Qt5.14.2\Tools\mingw730_32\bin;E:\Qt\Qt5.14.2\5.14.2\mingw73_32\bin;' + $env:PATH
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=E:/Qt/Qt5.14.2/5.14.2/mingw73_32 -DCMAKE_CXX_COMPILER=E:/Qt/Qt5.14.2/Tools/mingw730_32/bin/g++.exe
cmake --build build -j 4
ctest --test-dir build --output-on-failure
```

Для другого комплекта замените пути и используйте совместимый компилятор/разрядность. `BUILD_TESTING=OFF` отключает тестовые цели. Для упаковки динамической сборки скопируйте exe и `parameters.json` в отдельную папку и выполните `windeployqt --release --compiler-runtime <путь к exe>` из соответствующего комплекта Qt.

Для обнаруженного MinGW-комплекта также есть `tools/package.ps1`: скрипт копирует необходимые DLL и platform plugins напрямую. Это обходит неверные пути в перенесённой установке Qt, из-за которых местный windeployqt не находит platform plugin. Упакованная сборка проверяется с очищенным от Qt `PATH`.

Проверки включают JSON round-trip, валидацию, границы аргументов с пробелами/кириллицей, отрицательные bool-флаги, разбор regex из fit, обход разделов интерфейса, подбор и lifecycle сервера через тестовые исполняемые файлы и HTTP `/health`. Тестовая fixture не выполняет инференс. Для запуска реальной модели нужны собранные бинарные файлы llama.cpp и GGUF.

Поддержка статической сборки реализована: [STATIC-BUILD.md](STATIC-BUILD.md).

## Ограничения fit

При закрытии приложения всегда появляется вопрос «Да / Нет». Ответ «Нет» оставляет сервер и сборку работающими. Ответ «Да» останавливает запущенные процессы перед выходом. На Windows 10/11 сервер и fit запускаются в отдельных Job Objects: при аварии или принудительном завершении приложения Windows завершает также их дочерние процессы, освобождая занятую моделью память. Это относится к процессам, запущенным этим экземпляром Llama Studio; освобождение VRAM может занимать некоторое время у драйвера. На других ОС гарантируется остановка при обычном выходе.

[llama-fit-params](https://github.com/ggml-org/llama.cpp/blob/master/tools/fit-params/README.md) подбирает размещение по доступной памяти, а не измеряет максимальную скорость. Текущая утилита оценивает основную модель; проектор, draft-модель и адаптеры могут потребовать дополнительный запас `--fit-target`. Перед новым подбором сервер нужно остановить, чтобы освободить его память. Поддержка конкретного аргумента зависит от версии установленных бинарных файлов; неподдерживаемый аргумент будет виден в журнале llama.cpp.

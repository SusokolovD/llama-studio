# Llama Studio 0.10.0

Нативный менеджер локальных серверов llama.cpp и stable-diffusion.cpp на Qt.

Новое в 0.10.0:

- Отдельный движок stable-diffusion.cpp: выбор профиля, параметры, запуск/остановка `sd-server`, фактическая команда, журнал, проверка готовности и открытие поставляемого сервером Web UI.
- Сервер и папка весов выбираются независимо. Рекурсивный каталог распознаёт SD 2.x, FLUX.3 Image Klein, Qwen Image 2.1, Qwen3-VL 4B/8B и соответствующие VAE по заголовкам GGUF/Safetensors, включая переименованные файлы. Неизвестные семейства доступны через ручной профиль; неоднозначные зависимости требуют выбора.
- Каталог сохраняется в `image-models-cache.json`. Повторное открытие использует JSON; обновление перечитывает только изменённые заголовки. Незавершённые и повреждённые файлы не участвуют в подборе.
- Подбор компонентов и auto-fit: резерв VRAM, автоматический выбор GPU, CPU или несколько GPU одного backend. Окончательное размещение весов и рабочих буферов рассчитывает `sd-server --auto-fit on` при загрузке и генерации. Отдельного dry-run fit у проверенной сборки нет; размеры файлов не выдаются за точный расход памяти.
- Переносимые начальные настройки без путей конкретного компьютера и фиксированного номера GPU. Движок и профили изображений сохраняются в JSON. Поддерживаются старые профили llama.cpp; автоматически серверы не запускаются.
- Один движок за раз. Закрытие приложения останавливает сервер; защита Windows Job Object завершает дочернее дерево и при аварии приложения. Лимиты мощности из профиля применяются для обоих движков и сбрасываются при обычном выходе.

В архиве — статическая Windows x86-сборка LlamaStudio, способная запускать внешний 64-битный сервер. `sd-server`, его DLL и веса моделей в архив не включены. Совместимость проверена с Vulkan-сборкой stable-diffusion.cpp `fc350be`. Реальный SD 2.1 прошёл загрузку, API готовности и остановку; заголовки всех семи подготовленных компонентов распознаны. Генерация FLUX/Qwen в рамках проверки LlamaStudio не выполнялась.

Проверки: шесть наборов тестов MinGW и MSVC 2026, включая каталог, подбор компонентов/нескольких GPU, процессы, API и восстановление профиля; автономный запуск статического exe без Qt DLL. Статический MSVC x64-режим поддерживается CMake, для его сборки нужна соответствующая статическая Qt; опубликованный ZIP собран MinGW.

Ранее добавлено в 0.9.3:

- Выбор произвольного репозитория llama.cpp или форка во вкладке сборки. Поддерживаются URL и имена remote, дополнительно можно указать ветку. Pull выполняется в выбранной папке исходников из указанного источника.
- Репозиторий, ветка и пути сохраняются в JSON-профиле. Старые профили с пустым URL используют настроенный upstream локального клона. Сборка и копирование в llama-build работают по прежней схеме.
- Два скриншота интерфейса в README на GitHub.
- Тесты на локальных Git-репозиториях проверяют выбор форка вместо origin, ветку/HEAD, обработку недоступного репозитория и сохранение настроек.

Ранее добавлено в 0.9.2:

- Исправлено закрытие программы без прав администратора после отказа изменения мощности. Если лимит остался исходным или уже заводской, лишняя запись при выходе не нужна.

- Статическая сборка MinGW и совместимость с MSVC 2026 проверяются пятью наборами тестов, включая ошибки прав, выход и фильтрацию моделей. Тесты мощности используют имитатор, реальные лимиты GPU не изменяются.

Ранее добавлено в 0.9.1:

- Подтверждённые лимиты записываются в `gpuPowerLimits` текущего JSON-профиля. При открытом профиле его секция обновляется автоматически; при первом использовании сохраните профиль через «Сохранить как…».
- Перед запуском сервера лимиты из профиля применяются и проверяются. При обычном закрытии приложения изменённые GPU возвращаются к заводским лимитам. Ошибка сброса показывается пользователю.
- Заводские значения при выходе не заменяют выбранные лимиты в профиле. После аварийного/принудительного завершения сброс не гарантируется.

Ранее добавлено в 0.9.0:

- «Мониторинг → Мощность GPU»: выбор NVIDIA по UUID, текущий/заводской лимит, диапазон драйвера, ватты, заготовки процентов и возврат заводского значения.
- Перед применением читаются свежие пределы, затем выбранной карте отправляется команда и результат проверяется чтением. Лимиты не применяются при запуске приложения; закрытие окна не отменяет ручное изменение. Поддержка и права зависят от драйвера; для Windows могут понадобиться права администратора.
- Подробная встроенная справка о выборе баланса температуры, префилла, генерации и эффективности: одинаковые запросы, прогрев, условная таблица сравнения, формулы и несколько GPU.
- Управление проверено имитатором драйвера: отдельные карты, границы, отсутствие автоматических записей, возврат заводского лимита, ошибка доступа и отказ подтверждения. Реальная GPU использовалась только для чтения параметров.

Ранее добавлено в 0.8.0:

- Метаданные моделей сохраняются в общий `models-cache.json`. Повторное открытие каталога загружает снимок из JSON, помощник использует сохранённые метаданные неизменившихся файлов. Есть обновление каталога и принудительное перечитывание GGUF.
- Статический режим MSVC добавлен непосредственно в CMake: `LLAMA_STUDIO_STATIC_MSVC=ON`, static Qt, /MT для Release, /MTd для Debug. Для MSVC опция включена по умолчанию; требуется собственная статическая Qt подходящей архитектуры.
- При запуске загружается последний успешно открытый или сохранённый JSON-профиль. При недоступном/повреждённом файле загружаются настройки по умолчанию и показывается причина. Несохранённые изменения нужно сохранять вручную.
- Для основной модели, mmproj и draft-модели добавлен выбор из сохранённого JSON-каталога: «Все» или конкретная папка, поиск и кнопка выбора произвольного файла. Дополнительное сканирование при открытии списка не требуется.

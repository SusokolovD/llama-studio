# Llama Studio 0.9.0

Нативный менеджер локального сервера llama.cpp на Qt.

Новое в 0.9.0:

- «Мониторинг → Мощность GPU»: выбор NVIDIA по UUID, текущий/заводской лимит, диапазон драйвера, ватты, заготовки процентов и возврат заводского значения.
- Перед применением читаются свежие пределы, затем выбранной карте отправляется команда и результат проверяется чтением. Лимиты не применяются при запуске приложения; закрытие окна не отменяет ручное изменение. Поддержка и права зависят от драйвера; для Windows могут понадобиться права администратора.
- Подробная встроенная справка о выборе баланса температуры, префилла, генерации и эффективности: одинаковые запросы, прогрев, условная таблица сравнения, формулы и несколько GPU.
- Управление проверено имитатором драйвера: отдельные карты, границы, отсутствие автоматических записей, возврат заводского лимита, ошибка доступа и отказ подтверждения. Реальная GPU использовалась только для чтения параметров.

Ранее добавлено в 0.8.0:

- Метаданные моделей сохраняются в общий `models-cache.json`. Повторное открытие каталога загружает снимок из JSON, помощник использует сохранённые метаданные неизменившихся файлов. Есть обновление каталога и принудительное перечитывание GGUF.
- Статический режим MSVC добавлен непосредственно в CMake: `LLAMA_STUDIO_STATIC_MSVC=ON`, static Qt, /MT для Release, /MTd для Debug. Для MSVC опция включена по умолчанию; требуется собственная статическая Qt подходящей архитектуры.
- При запуске загружается последний успешно открытый или сохранённый JSON-профиль. При недоступном/повреждённом файле загружаются настройки по умолчанию и показывается причина. Несохранённые изменения нужно сохранять вручную.
- Для основной модели, mmproj и draft-модели добавлен выбор из сохранённого JSON-каталога: «Все» или конкретная папка, поиск и кнопка выбора произвольного файла. Дополнительное сканирование при открытии списка не требуется.

Ранее добавлено в 0.7.0:

- Узкий мониторинг 360×520 с режимом «Поверх окон», краткой сводкой железа и полными таблицами по кнопке «Подробно».
- Префилл и генерация в токенах/с из журнала запущенного сервера: промежуточные и итоговые отчёты, слот/задача, давность и длительность запроса. `--metrics` не требуется; без распознаваемых логов скорость остаётся неизвестной.
- Время работы процесса сервера, включая загрузку модели. Статистика переживает закрытие окна мониторинга и сбрасывается при перезапуске сервера.

Ранее добавлено в 0.6.1:

- Правильное определение локальной версии по `llama-server --version`: `0.8.0-dev`, `build 12024` и commit разбираются отдельно. Для сравнения с релизом b12024 используется номер сборки, не первая цифра semver.
- По кнопке проверки заново запускается локальная команда и запрашивается GitHub. Версия установленного exe видна и при ошибке сети; полный вывод, компилятор, архитектура и путь к exe доступны в подсказке.

Ранее добавлено в 0.6.0:

- Окно каталога GGUF: выбор папки, фоновое сканирование вложенных папок, фильтр/сортировка и параметры из метаданных. Выбор основной модели, проектора или draft-модели; обработка разделённых и повреждённых файлов.
- Окно мониторинга: CPU/RAM и история загрузки, температура/загрузка/VRAM/мощность/вентилятор каждой NVIDIA GPU через nvidia-smi. Для CPU и прочих температур поддержан отдельно запущенный Libre Hardware Monitor с WMI. Датчики зависят от оборудования; недоступные значения не выдаются за нули.
- Скрипт `tools/build-static-msvc2026.ps1` и CMake-пресет для MSVC 2026 x64 с /MT и проверкой зависимостей. Требуется собственная статическая Qt MSVC x64; в этом релизе готового MSVC static exe нет. Исходники скомпилированы MSVC 2026 с доступной динамической Qt; ZIP содержит MinGW static x86.

Ранее добавлено в 0.5.1:

- Встроенная справка по составлению промптов для локальных моделей для кодинга: цель, контекст, ограничения, критерии приёмки и формат ответа.
- Полезные формулировки и готовые шаблоны для реализации, поиска ошибки, ревью и агентской IDE.
- Передача кода и логов, экономия контекста, особенности instruct/FIM/reasoning и способы улучшить неудачный ответ. Ссылки на документацию Mistral и Qwen.

Ранее добавлено в 0.5.0:

- Контекст fit принимает `0`: автоматический подбор до максимума модели с учётом доступной памяти.
- Кнопки работают по всей площади, включая края.
- Подтверждение «Да / Нет» при каждом закрытии; ответ «Нет» выбран по умолчанию.
- На Windows 10/11 сервер, fit и их дочерние процессы завершаются системой при аварии приложения. Проверено принудительным завершением тестового процесса без выполнения деструкторов.

Ранее добавлено в 0.4.0:

- Расширенный помощник: отдельный справочник температуры, top-k/top-p/min-p, контекста, повторов, резерва памяти и рабочих пакетов.
- Вкладка «Память» с пересчётом KV-кэша, сравнением окон/f16/q8_0/q4_0 и бюджетом каждой GPU. Для неподдерживаемых схем вместо числа показаны ограничения и учебный пример.
- Отдельный build-commands.json, загрузка и сохранение рецептов, строгая проверка программы/массива аргументов и миграция старых строковых команд.

Ранее добавлено в 0.3.0:

- Обновление Git-репозитория llama.cpp, редактируемые команды сборки, журнал и отмена.
- Выбор папки готовых бинарников и копирование в отдельную llama-build с заменой файлов и откатом при ошибке.
- Версия в шапке и свойствах exe; иконка llama/терминала.
- Проверены git pull, замена файлов, отказ команды, отмена и откат на тестовых репозиториях. Компилятор и backend llama.cpp настраиваются под целевое оборудование.

- Русские названия и описания всех 261 параметра, подсказки для чата и агентского программирования.
- Помощник читает метаданные GGUF, учитывает обучающий контекст, число диалогов и формат KV-кэша.
- Обнаружение нескольких GPU через llama.cpp, выбор устройств, запас памяти каждой карты и режим CPU.
- Просмотр изменений, применение в JSON-конфиг и запуск llama-fit-params. Температура и шаблон не подменяются универсальным пресетом по умолчанию.
- Проверка релизов llama.cpp при запуске и по кнопке, управление сервером и журналом.

В assets: статическая Windows x86-сборка и SHA256. Qt, OpenSSL и runtime MinGW встроены; дополнительные DLL не требуются, кроме системных Windows. llama.cpp и модели устанавливаются отдельно. Приложение запускает и 64-битные серверы из выбранной папки.

Проверки: unit-тесты каталога/GGUF/нескольких GPU, GUI и lifecycle тестовых процессов, статические PE imports и запуск одного exe в чистой папке. Реальная скорость и качество зависят от модели и оборудования; используйте fit и проверяйте на своей задаче. Подробности сборки и сторонних компонентов находятся в архиве и репозитории.
